> 本文档基于对当前代码库的实测审核（2026-11-21），不是设想。
> 每条都注明：**现状证据 → 为什么要改 → 怎么改 → 验收标准**。

## 零、审核结论摘要

### 已经做得好的（不建议动）

| 项 | 证据 |
|---|---|
| 数据与 UI 解耦 | 引擎纯函数、无 I/O；路由与工具共用同一套逻辑 |
| 校验密度 | 1972 项自动检查，覆盖剧透泄漏、评分边界、畸形输入 |

## 一、P0：稳固工程基座（建议先做，约半天）

### 1.1 内联防漂移纳入自检 ✅ 本次已修一半

- **现状**：`scripts/inline-avatar-tab.mjs` 已改为幂等，支持 `--check`。
- **待办**：把 `--check` 接入 `selfcheck.mjs`，使其成为 1972 项检查的一部分。
- **改法**：

```js
// selfcheck.mjs 新增一组
group('generated code')
// 直接比对标记块与源码一致（不 spawn 子进程，避免 npm test 变慢）
```

- **验收**：故意改 `avatar-tab.js` 不改内联块 → `node scripts/selfcheck.mjs` 必须失败并指出原因。

### 1.2 化身进度持久化

- **现状**：刷新页面即丢失 `picks` / `step`。
- **改法**：`localStorage` 键 `mea:avatar:<id>`，存 `{ picks, step, tier }`，版本号跟随 `bundle.generatedAt` 的 schema 版本；读取时校验 scene id 仍存在（数据可能更新）。
- **不要**存到服务端：这是纯前端体验状态，存服务端反而引入一致性问题。
- **验收**：选两幕 → 刷新 → 回到第三幕且前两幕选择仍在；数据升级后旧存档被安全丢弃而非崩溃。

### 1.3 响应式与无障碍

- **改法**：
  - 加 `@media (max-width: 720px)`：格子降为单列，`.mea-drawer` 全宽，tab 条横向滚动（`overflow-x:auto`）。
  - 化身选项 `<button>` 已有，补 `role`/`aria`：选项组用 `role="group"` + `aria-label`；结果区用 `aria-live="polite"` 播报。
  - 进度条补 `role="progressbar"` + `aria-valuenow`。
  - 当前结论：`tabIndex` 不需要额外加，因为交互元素都是原生 `<button>`/`<input>`，本身可聚焦。
- **验收**：320px 宽度无横向滚动；仅键盘可完成一整段化身之旅；屏幕阅读器能读出进度与结果。

## 二、P1：内容扩充（收益最直接，约两三天）

### 2.1 化身从 6 位扩到 15 位

**依据**：22 位角色有 ≥2 个事件基础但尚无化身。

**优先级排序（按叙事张力与事件支撑）**：

| 顺序 | 角色 | 事件数 | 建议切入的抉择 |
|---|---|---|---|
| 1 | 波罗莫 | 4 | 阿蒙汉夺戒、临终悔悟 |
| 2 | 迪耐瑟 | 3 | 真知晶石、自焚前的抉择 |
| 3 | 法拉米尔 | 2 | 是否把魔戒送往刚铎 |
| 4 | 希优顿 | 2 | 被格里马蒙蔽、驰援刚铎 |
| 5 | 凯兰崔尔 | 4 | 水镜前拒绝魔戒 |
| 6 | 比尔博 | 3 | 拾戒、放下魔戒 |
| 7 | 索林 | 2 | 宝藏致疯、临终和解 |
| 8 | 萨鲁曼 | 2 | 从白袍到堕落 |
| 9 | 梅里/皮平（合并为"霍比特双人"） | 6/5 | 被俘、树胡、烽火 |
| 10 | 伊西铎 | 3 | 斩指后拒毁魔戒 |
| 11 | 索伦 | 10 | 铸戒、安纳塔欺骗（反派视角） |
| 12 | 凯勒布林博 | 3 | 铸戒、发现受骗 |

**每位的规格**（沿用现有不变式）：
- 3–4 幕，**每幕恰好一个原著选项**
- 每幕必须锚定一个真实 `event` 或明确标注 `event: null`（纯内心戏）
- 至少一幕 `tier: 3`（结局），让剧透控制有意义
- 每幕 `narration` ≥ 80 字，`result` 区分"会发生什么"与"为什么重要"

**验收**：`selfcheck` 的"每幕恰好一个原著选项"对 15 位全部成立；15 位 x 3+ 幕 ≈ 50 幕。

### 2.2 补足《霍比特人》的事件密度

- **现状**：《霍比特人》只有 2 个事件（TA 2941 远征、TA 2770 史矛革），而《魔戒》有 18 个。
- **改法**：拆细 2941，新增：食人妖遭逢、瑞文戴尔休整、迷雾山脉/哥布林、幽暗密林蜘蛛、木桶逃亡、长湖镇、史矛革之死、五军之战。约 +7 事件。
- **配套**：这些事件同时给索林/巴德/比尔博的化身提供锚点。

### 2.3 新增板块：氛围层（解决 A8）

**问题诊断**：现有 19 幕全是"做选择"，缺"读感受"。阅读小说时，代入感的另一半来自场景本身。

**方案**：在每幕抉择**之前**插入可选的「场景细读」折叠块——2–4 句环境/感官描写（气味、光线、声音），不参与评分。

- 数据结构：`scene.atmosphere: string`（可选字段，向后兼容）
- UI：`<details>` 原生折叠，默认收起，不打断节奏
- 验收：不改变任何现有评分逻辑；`selfcheck` 允许该字段缺失

### 2.4 名句补全与"角色声音"

- 给阿拉贡、索林等补专属名句（A7）
- **新增**：每位可扮演角色一个 `voice` 字段（一句话口吻描述，如"缓慢、克制，习惯用反问"），显示在化身卡上，帮助玩家进入角色。

## 三、P2：功能扩展（有想象力，但要克制）

### 3.1 关系图谱的"时间切片"

- **现状**：图谱是静态全量，看不出"谁在什么时候出现"。
- **改法**：加纪元滑块（第一→第四纪元），只显示该纪元已有事件涉及的角色；边也按事件过滤。**纯前端实现**，数据已足够（`EVENTS.characters`）。
- **验收**：拖到第二纪元只剩该期人物；与现有 focus/阵营高亮可叠加。

### 3.2 化身结局的"平行宇宙"对比

- **现状**：评分只告诉你偏离了几次。
- **改法**：结束页加"如果全走原著"的对照视图——并排显示你的路径 vs 原著路径，突出分歧点。
- **价值**：这是"代入"最有教学意义的落点，且不需要新数据。

### 3.3 作品导读的时间预算

- **现状**：入门路线有顺序，但没有"要花多久"。
- **改法**：给每部作品加 `readingHours` 区间（原著约 15–20h，电影约 9h，剧集约 16h），路线页显示累计时长。
- **注意**：这是估算，需标注"约"。

### 3.4 我**不建议**做的

| 想法 | 不做的理由 |
|---|---|
| 开放式 LLM 角色对话 | 会脱离数据、无法验证、可能讲错原著；正是当前设计刻意避开的 |
| 3D 地图 / 重型可视化 | 收益与体积不成正比；DSH 面板是文字优先场景 |
| 用户上传自定义角色 | 引发内容审核与版权风险，且破坏 canon 标注体系 |
| 账号 / 云同步 | 单机插件，引入后端运维成本远超收益 |

## 五、风险与边界

1. **数据仍未在线核对**。所有扩充都是基于作品常识的人工整理。扩充越多，越需要一次系统性校订（建议把 `data.js`/`lore.js` 导出为清单，逐条比对原著）。
2. **IP 边界**。化身剧本是原创叙述 + 原作事实的转述，**没有复制原文段落**。名句部分引用短句属合理引用范畴，但若上架市场，`QUOTES` 是最可能被要求处理的部分。扩充时不要增加长段原文。
3. **`journey.js` 会变长**。15 位 × 3–4 幕 ≈ 800–1000 行。建议届时按作品拆分为 `journey-fellowship.js` / `journey-hobbit.js`，再由 `journey.js` 汇总导出——但**现在不要提前拆**，避免过度设计。
4. **内联机制的天花板**。若面板继续变大，单文件 `client.js` 会越来越难维护。真正的解法是引入构建步骤，但那会让"改一行即可生效"的开发体验变差。当前规模（87 KB）尚可接受，**到 150 KB 时应重新评估**。

**执行中发现并修复的额外缺陷**（原方案未预见）：

1. 内联脚本硬编码了 builder 签名，导致新增的 `storage` 参数没有进入生成块 —
   探针以 "storage is not defined" 捕获。已改为**原样保留参数列表**。
2. 存储适配器最初被放在生成块内部，重跑内联时被整体覆盖删除 —
   已移到 `avatar-tab:end` 标记**之后**，并加校验确保其存在。
3. 自检里 "div 点击目标" 的正则跨越元素边界，把容器内的 button 误判为可点击
   div（2 处假阳性）。已收紧为只匹配 div 自身属性对象。

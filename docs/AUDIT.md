## 二、发现的问题（按优先级）

### P1｜存档校验有两套实现（架构债）

**证据**：`storage.js` 的 `validateSnapshot()` 与 `client.js` 中适配器的 `restore()` 各自实现了一套完全相同的校验规则（版本、未知场景、越界选项、step 钳制、tier 白名单），逐条比对后**当前规则一致**。

**为什么是问题**：这正是 P0 里"内联漂移"的同类风险——两份代码今天一致，明天改一处就分叉。而分叉的后果是**存档行为在 Node 测试与浏览器里不同**，极难发现。

**为什么当初会这样**：浏览器端无法 `import` Host 侧的 ESM 模块，只能内联。这是同一个约束在另一处的表现。

**建议**：
- 方案 A（推荐）：把校验逻辑压成一段**纯字符串源码**，由两边各自 `new Function` 求值——一份源码，两处执行。
- 方案 B：接受重复，但加一条 selfcheck 断言：两侧必须包含同一组规则关键字，任何一边增删规则就报错。
- 不建议：为这点逻辑引入构建步骤。

**当前缓解**：`probe-storage.mjs` 已在模拟 localStorage 下跑通浏览器侧；`selfcheck` 覆盖 Node 侧。两侧**行为**都被测了，只是不保证同源。

### P2｜内容覆盖不均

**证据（实测）**：

| 缺口 | 现状 |

| 未被化身锚定的事件 | 14 / 33（尤其第二纪元：e1–e6 六连空） |
| 未被化身用到的地点 | 8 / 27（米那斯魔窟、法贡森林、风云顶等） |
| 《霍比特人》事件已补齐，但第二纪元几乎没有可玩内容 | — |

**影响**：时间线与化身两个板块**对不上**——玩家在时间线上看到"努门诺尔沉没"，却找不到任何可扮演的视角。

**建议**：新增 2–3 位第二纪元化身（凯勒布林博、伊西铎、阿尔-法拉松），或把第二纪元事件标注为"暂无可玩视角"，避免期待落空。

### P3｜`client.js` 体积接近警戒线

**证据**：98.9 KB / 1873 行。ROADMAP 里自设的警戒线是 150 KB。

**分析**：其中约 220 行是内联的 avatar-tab，其余是 11 个标签页 + 全部样式。

**建议**：暂不拆分。但**下一次大改前**应评估：把样式抽成独立 CSS 字符串模块，或引入构建步骤。现在拆是过度设计。

### P4｜文档分散，缺入口

**证据**：`docs/` 下有 5 个文档（DETAIL、PLAN-P0、PLAN-ATMOSPHERE、PUBLISHING、ROADMAP），共 600+ 行，但 README 只链了 PUBLISHING。

**建议**：README 加一个"文档导航"小节。

## 三、做得好的（不建议动）

1. **确定性优于生成式**。化身不接 LLM，避免讲错原著——这个取舍贯穿始终，是正确的。
2. **不变式被测试而非被假设**。"每幕恰好一个原著选项"由 3200 项检查守着，写作时确实抓到过真实违规。
3. **降级路径完整**。存档失败、localStorage 抛异常、数据版本变化，全部有测试。
4. **来源诚实**。每条内容标注原著/电影/剧集，改编差异单独成页。
5. **方案先于代码**。三次任务都是"方案 → 自查 → 执行"，自查累计拦下 7 个会导致返工的设计错误。

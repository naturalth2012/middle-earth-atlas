# 三体宇宙架构分析，与中土图鉴的对照

> 2026-11-21。基于对本机 `three-body-atlas` 插件的实测源码，非印象描述。

---

## 一、三体宇宙的架构设计

### 1.1 分层结构

```
data/                    ← 7 个文件，按知识域拆分
  characters.js  (1326 行)   角色 + 阵营 + 关系
  lore.js        (1167 行)   地点 + 科技 + 术语
  timeline.js     (601 行)   纪元 + 事件
  plot.js         (749 行)   剧情节点 + 主题辩证
  works.js        (106 行)   作品元数据
  spoiler.js      (124 行)   ★ 剧透分级规则
  index.js         (34 行)   查表汇总

engine.js  (1169 行)    纯查询 + 图算法，无 I/O
sim.js     (1136 行)    ★ 零依赖物理模拟，纯数值
index.js    (696 行)    24 条路由 + 10 个工具
client.js  (2904 行)    单文件 UI，无构建步骤
```

**关键特征**：数据层按**知识域**而非**文件大小**拆分。`spoiler.js` 只有 124 行却是独立文件，因为它承载的是**一条横切规则**，不是一堆数据。

### 1.2 三个最有价值的设计模式

#### 模式 A：剧透分级是「横切系统」，不是「某个功能的开关」

```js
// 每个作品有阅读顺序号
WORK_TIER = { 'ball-lightning': 0, 'three-body': 1, 'dark-forest': 2, 'deaths-end': 3 }

// 任何记录的等级由它出现的作品【自动推导】
tierOf('character', c) → tierOfWork(c.firstWork)
tierOf('event', e)     → tierOfWorks(e.works)   // 取最晚的作品
tierOf('quote', q)     → tierOfWork(q.work)

// 统一门控，覆盖所有实体类型
gateOne(kind, record, maxTier)
gateList(kind, list, maxTier)
```

**遮蔽而非删除**：

```js
MASKED_FIELDS = ['details', 'desc', 'fate', 'detail', 'outcome', 'summaryLong']
maskRecord(record, tier, maxTier) {
  if (tier <= maxTier) return record
  const out = { ...record, locked: true, tier }
  for (const field of MASKED_FIELDS) delete out[field]
  return out   // 标题与一句话简介保留
}
```

> 注释原话：「Never deletes the record: the title and one-line summary stay visible so the reader knows what exists without being told how it ends.」

**这是设计的精髓**：读者知道「有这个东西」，但不知道「它怎么收场」。

#### 模式 B：独立算法模块（sim.js）

1136 行零依赖数值积分，不是预置结论：

- `simulate(config)` — 真实的三体引力积分，返回轨迹
- `sensitivity()` — 蝴蝶效应测量（改 1e-10 看偏差放大）
- `stabilityScan()` — 随机初值扫描，统计恒纪元比例
- `darkForest()` / `deterrence()` — 把小说的核心论证**做成可运行的模型**

**意义**：结论不是"我说黑暗森林成立"，而是"给你参数，自己跑，看它成不成立"。**可验证的论证**。

#### 模式 C：主题辩证（不预设答案）

```js
{
  id: 'survival-vs-morality',
  question: '为了文明的延续，可以牺牲多少人性？',
  sides: [
    { name: '维德的答案', view: '道德是文明吃饱之后才谈的东西…' },
    { name: '程心的答案', view: '如果为了活下去就先把人变成兽…' },
    { name: '章北海的答案', view: '两者都要，但顺序不能错…' },
  ],
  discussion: '假如人类真的靠兽性活了下来，活下来的还能叫人类文明吗？'
}
```

三方立场 + 一个**不给结论的开放问题**。这是知识库罕见的诚实：承认有些问题没有答案，比假装有答案更有价值。

### 1.3 规模指标

| 项 | 数值 |
|---|---|
| 代码总量 | 约 6400 行 |
| 数据层 | 7 文件，约 3500 行 |

## 二、中土图鉴 vs 三体宇宙

### 2.1 结构对比

| 维度 | 中土图鉴 | 三体宇宙 | 差距 |
|---|---|---|---|
| 数据层文件 | 3（data/lore/journey） | 7（按域+1 规则文件） | 中土偏合并 |
| 剧透控制 | 仅化身场景有 tier | **全实体门控** | **显著** |
| 遮蔽策略 | 场景直接不返回 | 保留标题+摘要，遮蔽详情 | **显著** |
| 独立算法 | 无 | sim.js 1136 行 | **显著** |
| 主题辩证 | 无 | 7 组三方辩证 | **显著** |
| 概念依赖图 | 有（人物关系图） | 有（概念跨类型图） | 各有侧重 |
| 化身体验 | 43 幕 + 氛围层 + 存档 | journey 路由 | **中土更强** |
| 路由 / 工具 | 17 / 8 | 24 / 10 | 三体更全 |

### 2.2 中土图鉴更强的地方

1. **化身玩法深度**：43 幕、90 抉择、剧本式后果、氛围层、存档、评分。三体的 journey 更轻。
2. **氛围层**：`atmosphere` 四感官结构，三体没有对应设计。
3. **来源分层 + 改编差异页**：10 处原著 vs 改编对照，三体的 `differences` 侧重剧集，没这么细。
4. **工程护栏**：3219 项校验 + 3 探针 + 内联防漂移 + 存储同源化。三体的 selfcheck 更轻。

### 2.3 中土图鉴明显缺失的

#### 缺口 1：剧透控制是「局部」而非「全局」

**证据**：我的 `tier` 只作用于 `journey.js` 的场景。而 `data.js` 里弗罗多的 `fate` 是「重伤后西渡，离开中土」——**读第一部的人打开人物卡，立刻被剧透结局**。

我甚至有 `characterDetail()` 直接返回 `fate`、`details`，没有任何门控。这在三体的设计里是不可接受的。

#### 缺口 2：没有可运行的论证

三体能跑引力模拟；中土只能陈述。但中土其实**有可算的东西**：

- 关系网络的**中心性**（谁是中土关系最密的人？）
- **路径长度分布**（任意两人的平均距离）
- 阵营间的**桥接人物**（连接两个阵营的关键节点）

这些不需要模拟器，但能把"关系图谱"从**展示**变成**分析**。

#### 缺口 3：没有主题辩证

中土的主题（怜悯 vs 决断、命运 vs 自由意志、权力 vs 腐化）同样值得做三方辩证，但完全没有。

## 三、可以吸收的模式（按性价比排序）

### 吸收 1｜全局剧透门控（强烈推荐）

**做法**（照搬三体的横切模式）：

```js
// 数据层：给作品标阅读顺序
WORK_TIER = {
  'hobbit-book': 1, 'lotr-book': 2, 'silmarillion': 3,
  'hobbit-films': 1, 'lotr-films': 2, 'rop': 3,
}

// 每条记录自动推导，不手工标注
tierOf('character', c) → tierOfWorks(Object.keys(c.works))
tierOf('event', e)     → tierOfWorks(e.works)
tierOf('place', p)     → tierOfWorks(p.works)
tierOf('artifact', a)  → tierOfWorks(a.works)

// 遮蔽而非删除
MASKED = ['details', 'fate', 'desc']
```

**适配中土的额外考量**：
- 中土有「原著/电影/剧集」三个来源层，与三体的「作品」不完全同构。需要 **来源层 × 阅读顺序** 二维，或用「最保守的层」作为等级。
- 《精灵宝钻》是前传但含大量第三纪元背景（如索伦起源），标 tier 3 会让读者以为要读完三部曲才能看它——**这是与三体的真实差异，不能照搬**。

**建议**：tier 按「信息揭示了多晚的情节」而非「作品出版的顺序」。霍比特人里的魔戒只是"一枚戒指"，lotr 才揭示身份——所以含"魔戒即至尊戒"的记录应是 tier 2。

### 吸收 2｜主题辩证（推荐，成本低）

**做法**：新增 `themes.js`，7 组辩证：

| 主题 | 问题 | 三方 |
|---|---|---|
| 怜悯与决断 | 对咕噜的怜悯是智慧还是软弱？ | 甘道夫 / 山姆 / 弗罗多 |
| 命运与自由 | 预言是约束还是借口？ | 埃尔隆德 / 伊欧玟 / 阿拉贡 |
| 权力与腐化 | 力量本身有善恶吗？ | 凯兰崔尔 / 萨鲁曼 / 波罗莫 |
| 苟活与抵抗 | 洛汗该守还是该逃？ | 希优顿 / 格里马 / 伊欧墨 |

**成本**：纯数据，1 天。**收益**：把"知识点"升维成"可讨论的问题"。

### 吸收 3｜关系网络的量化分析（推荐）

**做法**：新增 `analysis.js`：

- **中心性**：计算每位角色的度/中介中心性，回答"谁是中土最核心的人"
- **平均距离**：任意两人平均几跳
- **桥接者**：移除后网络分裂的角色（如埃尔隆德、甘道夫）
- **阵营连通性**：哪些阵营之间只有单点连接（脆弱）

**为什么值得**：这正好回答我在 AUDIT 里发现的问题——关系数据有 205 条，但只被"展示"，没被"分析"。而且**不需要新数据**，纯计算。

### 吸收 4｜数据层按域拆分（可选）

**现状**：`data.js` 1031 行 + `lore.js` 476 行 + `journey.js` 1545 行。

**三体的做法**：7 个文件，每个对应一个知识域，`spoiler.js` 单独存在因为它是规则不是数据。

**建议**：**暂不拆**。理由：
- 中土的总量（约 3000 行数据）还没到三体的 3500 行
- 拆分收益主要是可读性，但会打乱现有 import
- **真正该拆的信号是**：`journey.js` 超过 2000 行时（现在 1545）

### 不建议吸收的

| 模式 | 不吸收的理由 |
|---|---|
| 物理模拟器 | 中土没有可积分的物理系统。"魔戒腐蚀"是叙事不是微分方程。硬做会变成伪科学。 |
| 剧集/动画多版本对照 | 中土只有一版电影 + 一版剧集，三体有四版。差异页已覆盖。 |
| 24 条路由的规模 | 路由多不等于好。中土 17 条已覆盖需求，加路由要有明确用户场景。 |

## 四、结论

**三体的架构比中土更成熟的地方，不在代码量，在「系统性」**：它把剧透当成横切规则而非功能开关，把论证做成可运行代码而非陈述，把主题做成开放问题而非知识点。

**中土更强的地方在「纵向深度」**：化身玩法 43 幕的叙事密度、氛围层、存档、评分，是三部曲阅读体验的核心，三体没有做到这个深度。

**最该吸收的只有一条：全局剧透门控。** 因为这是**正确性问题**——现在读第一部的人点开弗罗多，就被告知他西渡了。这不是"少个功能"，是"体验被破坏"。

## 五、实证：剧透缺陷是真的

不是推测，实测结果：

```
characterDetail('弗罗多') 返回：
  fate:    重伤后于第四纪元随精灵西渡，离开中土。
  details: …在末日火山最终拒绝交出魔戒，被咕噜咬断手指后随其坠入烈焰…

characterDetail('山姆') 返回：
  fate:    回到夏尔与罗西成婚，成为夏尔市长。
```

**一个刚读完《霍比特人》、准备开始《魔戒》的读者**，打开人物图鉴想看"弗罗多是谁"，立刻被告知：
- 他会西渡（第四纪元结局）
- 他被咬断手指
- 咕噜坠入烈焰

这三条分别是第三纪元终章、末日火山、以及魔戒销毁方式——**全书最核心的三个悬念，在一次"查人物卡"里全部泄底**。

而且 `characterDetail()` 没有任何门控参数，UI 也没有任何"我读到哪了"的设置。

**这个缺陷的严重性高于我此前的所有功能缺失**，因为它直接影响第一类用户（新读者）的核心体验。P0 修。

## 六、实施建议（修正版优先级）

| 顺序 | 事项 | 工作量 | 性质 |
|---|---|---|---|
| 1 | **全局剧透门控** | 1 天 | 正确性修复 |
| 2 | 主题辩证（7 组） | 1 天 | 内容增维 |
| 3 | 关系网络量化分析 | 半天 | 展示→分析 |
| 4 | 数据层按域拆分 | 暂缓 | 未到阈值 |

**关于第 1 条的中土特化问题**（三体没有的）：

三体的 tier 等于"作品阅读顺序"，中土不能照搬，因为：

| 冲突 | 说明 | 处理 |
|---|---|---|
| 《精灵宝钻》是前传 | 但含索伦起源、炎魔来历等第三纪元背景 | 不整体标 tier 3，按**信息内容**而非作品定级 |
| 霍比特人里的"戒指" | 当时只是"一枚魔法戒指"，LotR 才揭示身份 | 含"魔戒即至尊戒"的记录 → tier 2 |
| 电影与原著进度不同 | 电影压缩了时间线 | 以**原著**为准定级，电影观众可能提前看到 |

**结论**：中土的 tier 应按「**这条信息揭示了多晚的情节**」定级，而不是「它出自哪部作品」。这是三体模式不能直接照搬、必须本地化改造的地方。
